## Consequences for the migration plan

1. **No real user corpus exists beyond ~55 projects / 106 chapters, and it is almost certainly synthetic** (generated by the audit/test scripts in `output-test-2`). Treat it as a *shape* reference and a golden-fixture seed, not as irreplaceable user work. Take a backup before any destructive step regardless.
2. **The migration round-trip contract has no meaningful real corpus to run against.** v4 §24's "SQLite round-trip preserves canonical story data" must be validated against a purpose-built fixture that exercises every story-domain table, including the 17 empty ones — otherwise a bug that only affects `world_entities` or `story_promises` will ship undetected.
3. **`UNIQUE(user_id)` on `subscriptions` is confirmed present in production**, so the V4-2 duplicate-registration concern is a *code-path* question (does `auth.ts` route every registration through one insert?), not a schema gap. The constraint already exists to protect the data.
4. **`semantic_cache` has only its primary key — no unique constraint on `(cache_type, input_key)`.** Confirms audit finding 1.4: `onConflictDoNothing()` in `semantic-cache.ts:76` and `headroom-summarize.ts:128` **cannot dedupe**, so concurrent identical inserts will create duplicate rows. This is now a verified production defect, and it is the reason 25 cache rows may not match 25 distinct keys.
5. **The `pwd_reset_tokens` index typo did not take effect** — `password_reset_tokens` is indexed and the typo'd variant does not exist. Audit finding 1.3 stands for the *script* (it silently no-ops) but the production database is correct.
